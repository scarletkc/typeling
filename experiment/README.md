# 实验：手写权重能否达到训练出来的水平

任务：英文单词补全（可利用同一段落的前文）。在 WikiText-2 上模拟打字，比较不同来源的权重。

## 参赛档位

| 档位 | 权重从哪来 | 可以用的数据 |
|---|---|---|
| baseline | 现有模型（B0：前缀匹配 + wordfreq 词频） | — |
| H0 纯规则 | 按规则手写，不看任何语料统计 | `vocab.txt` |
| H1 公式计算 | 从语料统计直接算出（计数、PMI、SVD…），不做梯度下降 | `vocab.txt`、`train.txt` |
| H2 LLM 写权重 | 由 LLM 按 weight-space programming 的方式直接写出，不用梯度 | `vocab.txt`、开发集评测结果（含出错样例），最多 50 次评测 |
| ref 现成模型 | 现成的预训练语言模型，只作对照（不受体积上限） | 自带的预训练 |

原计划的 T（自己训练同体积的小网络）不做了，改用现成的预训练模型 Pythia-14M 对照。

注意：H2 的"写手"本身是训练出来的模型，所以 H2 达标说明的是"知识可以不经梯度下降直接写进小网络"，不是"完全不需要训练"。

## 公平规则

- 除 baseline 外，所有模型使用同一份词表 `data/wikitext2/vocab.txt`（训练集出现 ≥2 次的纯字母词，36,300 个，只有词、没有次数）。
- 体积上限 5 MB（模型自己的文件总大小，允许压缩；共享词表不计）。ref 不受此限。
- 测试集封存：调试只用开发集；每个模型最终只用 `--final` 在测试集上跑一次。
- 写 H0 / H2 时不读 `train.txt` 原文，也不看测试集。
- 所有模型都只看本段落的前文。

## 指标

在 `evaluate.py` 开头有完整定义。简述：

- **KSR**：按键节省率。第一个候选就是目标词时按 Tab 接受（算 1 键）。
- **acc@i**：已打 i 个字母时第一个候选正确的比例；acc@0 即"预测下一个词"。
- **top3@0**：下一个词在前 3 个候选里的比例。
- **OOV**：目标词不在模型词表里的比例。
- 体积、加载时间、每键预测耗时。

## 运行

```bash
uv run experiment/prepare_data.py                 # 下载并整理数据（一次）
python experiment/evaluate.py B0 H2               # 开发集评测，结果追加到 results.jsonl
python experiment/evaluate.py H2 --errors 40      # 附带随机出错样例
uv run --no-project --with torch --with transformers python experiment/evaluate.py P14M   # 对照模型
python experiment/evaluate.py B0 --final          # 测试集（只在最终比较时）
```

新模型：在 `models.py` 里继承 `Model`（或 `ScoreModel`：只需给整个词表打分），登记到 `REGISTRY`。

## 结果（开发集，172,231 个目标词）

| 模型 | 档位 | KSR | acc@0 | acc@1 | acc@2 | acc@3 | top3@0 | OOV | 体积 | 每键 |
|---|---|---|---|---|---|---|---|---|---|---|
| B0 | baseline | 17.13% | 8.53% | 20.99% | 27.22% | 33.63% | 13.99% | 3.69% | 0.88 MB | 22.5 µs |
| H2 v0（零样本） | H2 | 24.36% | 13.72% | 32.14% | 40.06% | 44.77% | 23.09% | 4.60% | 0.11 MB | 5.4 µs |
| H2 v1 | H2 | 24.60% | 14.30% | 32.54% | 40.63% | 45.11% | 23.48% | 4.60% | 0.12 MB | 4.8 µs |
| H2 v2 | H2 | 24.69% | 14.25% | 32.62% | 40.93% | 45.28% | 23.48% | 4.60% | 0.12 MB | 4.8 µs |
| Pythia-14M（近似，偏低） | ref | **36.20%** | **23.57%** | **45.15%** | **54.97%** | **61.88%** | **35.66%** | 4.60% | 28.14 MB | 7.2 µs |

H2 已用开发集评测 4 / 50 次（第 2 次是同一个 v0 重跑一遍看出错样例）。

### H2 是什么

`h2_handwritten.py`，118 KB，约 9,400 个手写数字，没有梯度下降、没读训练集：

- 词频：2,231 个词分 24 档写 Zipf 值，其余按词形从词根推、再按长度给默认值；
- 语法头：功能词表 + 词尾规则判词类，638 个"前一个词类 → 下一个词类"的加减分，a / an 按读音修正；
- 搭配头：207 个 1～3 词上下文的下一个词概率（6,098 个数）+ 241 条介词固定搭配；
- 复制头：段落里出现过的实词加概率；归纳头：上次"前一个词"后面跟的词加概率（A B … A → B）。

### Pythia-14M 怎么接入、有什么偏差

- EleutherAI/pythia-14m，1400 万参数，Apache-2.0。它的训练语料 the Pile 含维基百科，可能见过这些文章，分数可能偏高。
- 子词模型变成整词补全：每个词取小写 / 首字母大写两种写法，第 1 个子词的概率按真实前文算，
  后面的子词和"词到此结束"的概率用不看前文的近似（`lm_reference.py` 开头有说明）。
  这个近似拿不到前文里重复出现同一个罕见词的好处，所以表里是 Pythia 的偏低估计。
- 段落按原始大小写、还原成正常排版后送进模型（其他模型只看小写）。

### 目前的结论

体积大约 240 倍的 Pythia-14M，即使按偏低的方式估计，KSR 也比手写的 H2 高 11.5 个百分点，
预测下一个词（acc@0）高 9.3 个百分点。手写权重从 B0 的 17% 推到了 25%，但离训练出来的小模型还有明显差距。
